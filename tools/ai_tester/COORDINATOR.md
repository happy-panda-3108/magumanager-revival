# AI 테스터 코디네이터 안내 (엔진 세션, 2026-11-19)

게임 주인(11-19): "전부 다 합시다. 어떻게든, 테스터가 실행될 때 사용되는 토큰 양만 줄이면 돼."
11-19 회차의 측정값은 테스터 한 명이 2시간에 토큰 33만~40만, 도구 호출 150~230번, 캡처 60~100장이었습니다. 비용 대부분은 호출마다 쌓인 맥락 전체를 다시 보내는 데서 나왔습니다.

## 바뀐 구조
1. **짧은 회차.** 테스터 한 번 실행은 도구 호출 60번 또는 30분까지입니다. 리그 결과를 기다리지 않고 끝냅니다. 다음 회차는 새 에이전트로 엽니다(state.md만 들고 시작하니 맥락이 작습니다). 끝난 에이전트를 SendMessage로 다시 깨우지 않습니다. 깨우면 쌓인 맥락 전체를 다시 읽습니다.
2. **처음에 읽는 것 셋.** TESTER_BRIEF_5.md(약 8 KB), 자기 state.md(3 KB 안팎), RUN_NOTE.md(2 KB 안팎)입니다. notes.md·리뷰·참고서는 Grep으로만 봅니다.
3. **글로 보기.** 원격 명령 ui·text·tap과 작은 shot을 씁니다(tester_1119d부터). look.ps1 한 번이 캡처 한 장을 대신합니다.
4. **매크로.** results·missions·exhibition·look(tools\ai_tester\macros)과 state.py(DB 읽기 전용)가 있습니다. 스킬 ma9m-tester로 불러 씁니다.
5. **인원 돌리기.** 한 번에 여섯 명을 모두 돌리지 않습니다.
   - 확인 회차: 고친 것 확인 목록을 둘에게 나눕니다(30분).
   - 탐색 회차: 한두 명이 새 기능을 손으로 봅니다(30분).
   - 자급자족(6)은 하루 한 번 30분만 합니다.
   - 밤에도 한 회차에 2~3명, 회차 사이는 1시간 이상 둡니다.
6. **모델 나누기.** 확인 회차와 자급자족처럼 매크로가 많은 회차는 `model: "sonnet"`으로 엽니다. 리뷰를 깊이 써야 하는 탐색 회차만 기본 모델로 엽니다. 처음 몇 회차는 sonnet 회차의 리뷰가 쓸 만한지 코디네이터가 봅니다.

## 회차 여는 순서
1. RUN_NOTE.md를 새로 씁니다(2 KB 안팎): 빌드, 마감, 이번에 볼 것, 테스터별 한 줄.
2. `tester_build.txt`를 확인하고 클라이언트를 켭니다. 켤 때는 테스터 사이에 20초를 둡니다(`start_remote.ps1`).
3. 에이전트를 엽니다. 프롬프트는 아래 틀 그대로 씁니다(짧게).
4. 끝나면 각자의 15줄 보고를 모아 남은일목록에 넣습니다. 클라이언트는 끕니다(`close_testers_at.ps1` 또는 그 자리에서).

```
게임은 포트 <포트>에 켜져 있다. 마감 <시각>, 도구 호출 60번 또는 30분, 캡처 15장까지다.
끝낼 때 state.md를 새로 쓰고, notes.md 끝과 리뷰 끝에 덧붙이고, 15줄 안으로 보고한다.
```
